# 模型面板动效：参考片实测

参考素材：`/tmp/ref.mp4`（9.43s，1180×2556，HEVC，容器 59.94fps）。
内容是竖屏短视频里翻拍的一台笔记本屏幕，屏幕里是一个 macOS 浮层模型选择器。

## 0. 测量方法

```bash
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate /tmp/ref.mp4
ffmpeg  -v error -ss <t> -i /tmp/ref.mp4 -frames:v 1 -vf "crop=W:H:X:Y" frame.png
ffmpeg  -v error -ss <t> -t <d> -i /tmp/ref.mp4 -vf "crop=..." -f rawvideo -pix_fmt rgb24 out.raw
```

`rawvideo` 交给 Python 逐像素读（本机没有 Pillow，raw 是不需要解码器的格式）。
时序来自逐帧帧差；颜色来自对条带区域做逐行 / 逐列亮度平均和分区取色。

**内层其实是 30fps。** 容器是 59.94fps，但每两帧的像素差约为 0，即原片 30fps 被补帧上来。
所以所有时间刻度的分辨率是 33ms，下面写的时长都有 ±33ms 的量化误差。

## 1. 入场时长

浮层本身是**从压缩状态弹出来**的，录屏开头正好录到了这段（t=0 之后约 0.23s 内完成）：

| 时刻 | 画面 |
| --- | --- |
| 0.067s | 列表只有淡淡的影子，文字几乎读不出来 |
| 0.100s | 五行全出来，但整体位置偏下 |
| 0.167s | 文字清晰，位置继续上移 |
| 0.233s | 稳定 |

- 整排文字的行距一直是 ~70–76px，**没有缩放、没有旋转、没有斜向扫光**，只有位移 + 淡入；
- 期间整排字的中心从 y≈194 走到 y≈174，即往上滑了 **约 20px**，是面板高度（~490px）的 **4%**；
- 时长 **约 0.17s**（0.067s → 0.233s）。
- 对照：画面里不相关的区域（右下麦克风按钮那块 100×100）亮度全程 115.6 → 115.0，
  所以这不是视频开场淡入，是浮层自己的入场。

第二次状态切换：点 `GPT-6 Astra` 那一行之后，六行列表收成一个胶囊。

| 时刻 | 画面 |
| --- | --- |
| 1.433s | 列表六行完整（最后一帧稳定列表帧） |
| 1.500s | 半透明过渡帧，新旧内容都不清晰 |
| 1.567s | 胶囊已成形（`轻量 / GPT-6 Astra` + 滑轨） |
| 1.70s | 帧差回落到地板值，收敛结束 |

- 切换本身：**0.10–0.15s**（30fps 只有一到两帧过渡）。
- 含收敛整段：**0.27s**（1.433s → 1.70s，帧差能量 3.3–4.9 → 2.0 地板）。

落到 SwiftUI 用的是 `spring(response: 0.32, dampingFraction: 0.82)`：
0.32s 的弹簧前 0.1–0.15s 完成主要的位移/透明度变化，尾段正好对应测到的收敛；
入场再叠一个 5pt 的上滑（面板高度的 4% 换算到 104pt 高的卡片）。
参考片里**没有级联**（六行是同时消失的），代码里留 20ms 的错峰只是为了让一排卡片
不要同一帧闪出来，不是从素材里量出来的。

## 2. 选中形变

- 选中的行（被点的那一行）保留下来变成胶囊的**标题行**，其余行一起收起；
- 没有横向位移、没有旋转、没有 3D 倾斜——过渡是一帧半透明的溶解；
- 胶囊在 1.567s 之后到 1.70s 之间还有轻微缩放/位移（收敛），幅度在拍摄抖动之下，量不出具体比例。

落到卡片轨道上：选中的卡留在 1.0，其余缩到 0.94、压到 0.85 透明度；
**删掉了 2.12.0 里那对 ±8° 的 `rotation3DEffect` 和 180px 的斜向扫光**——
参考片里这两样都没有。

## 3. 高光角度

取 t=4.30s 的紫条（`crop=560:300:320:880`），逐行统计亮度：

| 位置 | 条带逐行亮度 | 同一帧面板底色 |
| --- | --- | --- |
| 上沿 | 63 | 166 |
| 中段 | 52 | 167 |
| 下沿 | 43 | 172 |

条带从顶到底掉了约 20 个亮度单位（约 32%），而同一帧面板底色几乎是平的（166 → 173，
还是往下变亮的）。所以这个顶亮底暗**来自 UI 本身，不是屏幕反光**：高光在条带顶部边缘，
方向 **90°（顶光）**，不是斜向扫光。

条带自身的颜色是 **0° 横向渐变**，按左 / 中 / 右三段取平均：

| 时刻 | 左 | 中 | 右 |
| --- | --- | --- | --- |
| 3.60s | #1B3D97 | #2F3796 | #462F8F |
| 4.30s | #2A2487 | #4F319D | #4E2893 |
| 5.10s | #271E7D | #452A93 | #4E2D8D |

即深蓝 → 紫的横向过渡。落到选中卡片上是 `#1B3D97 → #4E2D8D` 的 `leading → trailing`
渐变（0.55 不透明度）+ 沿上边缘、向下淡出的 1pt 白线（90°）。

列剖面里还有 ±5 的起伏，那是条带上的静态闪点（✦）和指针边缘，不是移动的扫光带：
3.2–5.1s 之间没有稳定的斜向亮带，所以没有做扫光动画。

## 4. 没量出来的

- 胶囊的精确宽高比：拍摄有透视，面板和桌面都是浅色，边缘检测被文字边缘淹没；
- 弹簧的过冲量：收敛幅度在手持拍摄的抖动以下；
- 入场的缓动曲线形状：只有 0.067 / 0.100 / 0.167 / 0.233 四个可用采样点，够定时长，不够拟合曲线。

这些都不猜，代码里就不写。
